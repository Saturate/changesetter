Configuration lives in `changesetter.toml` at the repo root. The entire file is optional; changesetter auto-detects packages and uses sensible defaults.

## Packages

Override or supplement auto-detected packages:

```toml
[[package]]
name = "mylib"
path = "crates/mylib"
type = "cargo"

[[package]]
name = "my-frontend"
path = "apps/web"
type = "npm"
```

| Field | Description |
|---|---|
| `name` | Package name (used in changeset frontmatter) |
| `path` | Path to the package directory, relative to repo root |
| `type` | Ecosystem type: `cargo`, `cargo-workspace`, `npm`, `python`, `dotnet`, `helm` |
| `members` | For workspace types: `"all"` to bump all members together |

## Ignore

Packages that are auto-detected but should never be versioned:

```toml
ignore = ["examples", "internal-tools", "test-fixtures"]
```

Ignored packages are excluded from the release plan, changelogs, and tagging.

## Changeset directory

Changesets live in `.changeset/` by default, including any subdirectories. To keep them elsewhere:

```toml
changeset_dir = ".changeset/changesets"
```

The path must be relative to the repository root, use `/` as the separator, and stay inside the repository (no `..`). It is also used as a git pathspec by `changesetter check --base`. Symlinked directories inside it are skipped.

## Groups

### Fixed groups

Packages in a fixed group always bump together. If any member has a changeset, all members bump to the highest level in the group.

```toml
[groups.core]
fixed = ["core-lib", "core-macros"]
```

### Linked groups

Packages in a linked group share version numbers but only bump when individually changed. When multiple linked members bump in the same release, they coordinate to the highest bump level.

```toml
[groups.utils]
linked = ["util-a", "util-b"]
```

A package can only belong to one group.

## Dependency cascading

When package A bumps and package B depends on A, optionally cascade a bump to B:

```toml
update_internal_dependencies = "patch"
```

| Value | Behavior |
|---|---|
| `"patch"` | Always bump dependents by at least patch |
| `"minor"` | Only bump if the dependency range breaks (treated as `"patch"` in current version) |
| `"none"` | Don't cascade (default) |

Dependencies are detected from manifest files: `[dependencies]` in Cargo.toml, `dependencies`/`devDependencies` in package.json, `dependencies` in Chart.yaml.

## Changelog

```toml
[changelog]
file = "CHANGELOG.md"
per_package = true
none_bump = "section"
none_bump_heading = "Internal"
```

| Field | Default | Description |
|---|---|---|
| `file` | `"CHANGELOG.md"` | Changelog filename |
| `per_package` | `false` | When `true`, each package gets its own CHANGELOG.md in its directory |
| `none_bump` | `"section"` | How to handle none-bump entries: `"section"` (under a heading), `"omit"` (exclude) |
| `none_bump_heading` | `"Internal"` | Heading for none-bump entries when `none_bump = "section"` |

Single-package repos always use a single root CHANGELOG.md regardless of `per_package`.

### None-bump entries without a release

None-bump entries normally go under the `none_bump_heading` inside the version section being released. When a changelog gets none-bump entries but no new version (a release run with only `none` changesets, or with `per_package = true`, a package that isn't released this time), they go under an `## Unreleased` heading at the top of that changelog instead:

```markdown
# Changelog

## Unreleased

### Internal

#### Updated CI configuration

## 1.2.0 - 2026-07-25
...
```

Later runs add to the same section: new entries go under its none-bump heading, next to any hand-written subsections like `### Added`. A Keep a Changelog style `## [Unreleased]` heading is kept as spelled, and a new one uses brackets when the file's version headings do. New sections always go at the top, above every existing version.

The next release written to that changelog moves the section's contents into its new version section and removes the Unreleased heading. They then reach every place the release's notes go, exactly once: the changelog, the annotated tag message, the `changelog` field of `release --output json` and the GitHub release the release action creates. The release action's notes extraction never treats an Unreleased heading as a version.

A release run with only none-bump changesets creates no tags or GitHub releases. Its commit is `chore: add unreleased changelog notes` (or `chore: remove none-bump changesets` when `omit` leaves nothing to write), since there are no versions for `commit_message` to name.

With `per_package = true`, each package named in the changeset gets the entry in its own changelog. A repo-wide `default: none` changeset goes to every package's changelog, since this mode writes no root changelog. A private workspace root (`"private": true` with `"workspaces"`) or a manifest with no name doesn't count as a package here.

A changeset that bumps one package and is `none` for another (`a: minor`, `b: none`) is listed only in `a`'s release, in per-package mode too: `b`'s changelog doesn't get it.

With `none_bump = "omit"`, no Unreleased section is written.

## Tag format

```toml
[tag]
format = "v{version}"
```

| Placeholder | Value |
|---|---|
| `{version}` | The new version number (e.g. `0.2.0`) |
| `{name}` | The package name |

Defaults: `v{version}` for single-package repos, `{name}@v{version}` for monorepos.

## Release

```toml
[release]
commit_message = "chore: release {versions}"
tag_annotated = true
```

| Field | Default | Description |
|---|---|---|
| `commit_message` | `"chore: release {versions}"` | Commit message template. `{versions}` expands to `name@version, ...` |
| `tag_annotated` | `true` | Use annotated tags with changelog as the message. Set `false` for lightweight tags |

## Hooks

Commands to run after version bumps, before committing:

```toml
[hooks]
post_bump = ["cargo check", "cargo fmt"]
```

Hooks run in order, from the repo root. If any hook exits non-zero, the release aborts.

## Full example

```toml
[[package]]
name = "core"
path = "crates/core"
type = "cargo"

[[package]]
name = "web"
path = "apps/web"
type = "npm"

[groups.core]
fixed = ["core", "core-macros"]

ignore = ["examples"]

update_internal_dependencies = "patch"

[changelog]
file = "CHANGELOG.md"
per_package = true
none_bump = "section"
none_bump_heading = "Internal"

[tag]
format = "{name}@v{version}"

[release]
commit_message = "chore: release {versions}"
tag_annotated = true

[hooks]
post_bump = ["cargo check"]
```
