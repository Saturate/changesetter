## `changesetter init`

Create the `.changeset/` directory. Idempotent; succeeds if the directory already exists.

| Flag | Description |
|---|---|
| `--config` | Generate a starter `changesetter.toml` |

## `changesetter add`

Create a new changeset file.

| Flag | Description |
|---|---|
| `--package <name>` | Package(s) affected (repeatable) |
| `--bump <level>` | Bump level: `patch`, `minor`, `major`, `none` |
| `--no-bump` | Shorthand for `--bump none` |
| `-m, --message <text>` | Change description |

When run without flags in a terminal, prompts interactively for packages, bump level, and description. When stdin is not a TTY (CI), all flags are required.

## `changesetter check`

Verify that at least one changeset file exists. Used in CI to enforce changeset presence on PRs.

| Flag | Description |
|---|---|
| `--base <ref>` | Compare against a base branch (e.g. `origin/main`) |
| `--output json` | Write structured JSON to stdout |

Without `--base`, checks every changeset in the changeset directory. With `--base`, uses `git diff` to find the changeset files the current branch adds, changes or deletes, and fails if one of them can't be parsed. Changesets are read as committed at `HEAD`. A branch that only deletes changesets, like a version PR, passes.

The JSON has these keys:

- `changesets`: each changeset found, with its `file` (relative to the repo root), its `packages` as a map of package name to bump level, and its `summary` text. A changeset the branch deleted has `deleted: true` and no packages or summary.
- `bumps`: the highest bump level per package across those changesets.

The JSON is written even when no changeset is found (with an empty `changesets` list, and exit code 1), so CI can tell a missing changeset apart from a check that failed. A changeset that can't be parsed, or a base ref that isn't fetched, exits non-zero with no JSON.

## `changesetter status`

Show pending changesets and a preview of what the next release would look like. Read-only, no side effects.

| Flag | Description |
|---|---|
| `--output json` | Write structured JSON to stdout |

The JSON has these keys:

- `pending`: changeset file names, relative to the changeset directory and without `.md`.
- `packages`: every detected package with its current `version`, its `path` (`.` for the repo root), the `changelog` file it writes to, the `tag` for that version (following the configured tag format) and `tagged`, whether that tag exists locally. Run `git fetch --tags` first in CI.
- `tag_annotated`: whether `release` creates annotated tags (the `[release]` setting).
- `releases`: what a release would do now: `name`, `previous_version`, `version`, `bump` and `tag`. A package named in a changeset but not detected shows up here with `previous_version` `0.0.0` and no `packages` entry.
- `none_entries`: titles of changesets that document a change without bumping a version.

```json
{
  "pending": ["brave-foxes-dance"],
  "tag_annotated": true,
  "packages": [
    { "name": "mylib", "version": "1.0.0", "path": ".", "changelog": "CHANGELOG.md", "tagged": true, "tag": "v1.0.0" }
  ],
  "releases": [
    { "name": "mylib", "previous_version": "1.0.0", "version": "1.1.0", "bump": "minor", "tag": "v1.1.0" }
  ],
  "none_entries": []
}
```

## `changesetter version`

Bump versions in manifest files and update changelogs. Does not create git tags.

| Flag | Description |
|---|---|
| `--dry-run` | Show what would change, modify nothing |
| `--no-commit` | Update files but don't git commit |
| `--snapshot <tag>` | Create a snapshot version (e.g. `0.0.0-canary-20260801T120000`) |

Snapshot versions don't consume changesets, update changelogs, or create tags. They only update manifest files for preview builds.

## `changesetter release`

The full release pipeline: version bump, changelog, commit, and git tags.

| Flag | Description |
|---|---|
| `--dry-run` | Show the full plan without modifying anything |
| `--no-commit` | Modify files but don't commit or tag |
| `--output json` | Write structured JSON to stdout |

The JSON output is consumed by the GitHub Actions release action to create GitHub Releases.

When no changesets are pending, exits 0 with a message and no side effects.

## `changesetter pre`

Manage pre-release mode.

### `changesetter pre enter <tag>`

Enter pre-release mode. Subsequent releases produce versions like `1.0.0-rc.0`.

```bash
changesetter pre enter rc
changesetter pre enter beta
changesetter pre enter alpha
```

Creates `.changeset/pre.json` to track the pre-release state.

### `changesetter pre exit`

Exit pre-release mode. The next release produces stable versions.

### `changesetter pre status`

Show the current pre-release state.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success, including "nothing to do" for release with no pending changesets |
| 1 | Check failed (no changeset found), validation error (bad frontmatter, unknown package, unknown bump level) |
| 2 | Environment error (dirty working tree, git not found, not a git repo, base ref unavailable) |
