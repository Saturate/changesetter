## Install

From source:

```bash
cargo install changesetter
```

Or download a prebuilt binary (Linux, macOS, Windows):

```bash
curl -sL https://github.com/saturate/changesetter/releases/latest/download/changesetter-x86_64-unknown-linux-gnu.tar.gz | tar xz
```

### Verify a download

Every CLI release from 0.9.0 on publishes a `SHA256SUMS` file next to its archives, built by the same workflow run that built them. Pin a version and check the archive against it before unpacking:

```bash
VERSION=0.9.0
TARGET=x86_64-unknown-linux-gnu
BASE="https://github.com/saturate/changesetter/releases/download/changesetter%40v${VERSION}"
curl -fsSLO "${BASE}/changesetter-${TARGET}.tar.gz"
curl -fsSLO "${BASE}/SHA256SUMS"
grep " changesetter-${TARGET}.tar.gz\$" SHA256SUMS | sha256sum --check -
tar xzf "changesetter-${TARGET}.tar.gz"
```

On macOS use `shasum -a 256 --check -` instead of `sha256sum --check -`. The `grep` picks the one line for your archive, and `--check` exits non-zero if the file doesn't match.

The archives also carry a GitHub build provenance attestation, which proves they were built by this repository's Build Binaries workflow on GitHub Actions. With the GitHub CLI:

```bash
gh attestation verify "changesetter-${TARGET}.tar.gz" --repo Saturate/changesetter \
  --signer-workflow Saturate/changesetter/.github/workflows/build-binaries.yml
```

## Initialize

Run `init` in your repository root. This creates the `.changeset/` directory where changeset files live.

```bash
changesetter init
```

Optionally generate a starter `changesetter.toml`:

```bash
changesetter init --config
```

## Create a changeset

Interactive mode prompts for affected packages, bump level, and a description:

```bash
changesetter add
```

Non-interactive mode for CI scripts:

```bash
changesetter add --package mylib --bump patch --message "Fixed null handling"
```

For changes that don't warrant a version bump:

```bash
changesetter add --package mylib --no-bump --message "Updated CI config"
```

This creates a markdown file in `.changeset/` with a random name like `cool-dogs-dance.md`. See [Changeset Format](/changeset-format) for details on the file structure.

## Verify in CI

Add a check step to your pull request workflow. It fails if no changeset exists on the branch:

```bash
changesetter check --base origin/main
```

See [GitHub Actions](/github-actions) for ready-made workflow files.

## Preview the release

See what would happen without changing anything:

```bash
changesetter status
```

## Release

Run the full pipeline: bump versions in manifest files, generate CHANGELOG.md, commit, and create git tags.

```bash
changesetter release
```

Or preview first:

```bash
changesetter release --dry-run
```

The release command outputs JSON when run with `--output json`, which the GitHub Actions release action uses to create GitHub Releases.
